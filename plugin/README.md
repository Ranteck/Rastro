# Plugin de Claude Code para Rastro

Lleva el plan de la semana y los avisos de desvío a la sesión de Claude Code. Rastro es global: una configuración, un plan, un cron y un dashboard para todos tus repos, en `~/.rastro/`. Cada repo registrado guarda solo `.rastro/events.jsonl`. El plugin no instala nada ni escribe fuera de eso.

## Instalación

Con Node 22 y Claude Code, una vez: `/plugin marketplace add Ranteck/Rastro` y `/plugin install rastro@rastro`. Después, en cada proyecto, `/rastro:init`. Así sigue `main`. Se actualiza con `/plugin marketplace update rastro` y `/reload-plugins`.

Desde 0.1.x, corré `/rastro:init` otra vez en cada repo: los `plan.md` y `config.json` por repo dejan de usarse y no se migran. El daily automático global reemplaza a los de antes al instalarlo. El dashboard construido en 0.1.x no sirve con 0.2.0: `/rastro:init` lo reconstruye si `frontend/dist/version.txt` falta o no coincide con la versión del frontend.

Para desarrollo, `claude plugin marketplace add <ruta al clon>` o `claude --plugin-dir <ruta>/plugin` (no las dos cosas a la vez).

El plugin instalado corre desde una copia sin `backend/`; la CLI se busca en este orden: `$RASTRO_BIN`, `rastro` en el PATH y la raíz del repo que imprime `scripts/raiz-rastro.sh` (junto al plugin o en el marketplace clonado). Si no la encuentra, los hooks no hacen nada y los comandos avisan.

## Piezas

- `/rastro:init`: deja Rastro listo en el repo de una: escribirlo ya es el OK. Diagnostica sin escribir (CLI en el PATH, si el repo ya está registrado con `rastro siguiente --si-registrado`, si el `frontend/dist` de la raíz del repo es de la versión actual, con `scripts/dashboard-al-dia.sh`), dice lo que va a hacer y lo corre sin preguntar, con sus comandos preaprobados, y frena en el primer paso que falle. Los ajustes van como argumento (`sin cron`, `cron 19:00`, `sin dashboard`). Hace: instala la CLI (`npm install && npm link` en `<raíz>/backend`, si hay raíz), registra el repo (`rastro init`), instala el `daily` automático global (un solo cron para todos los repos, que reemplaza a los de antes; si ya está, no lo toca; 18:30 por defecto, editable), construye el dashboard (si falta o es de otra versión) y termina con `rastro plan --desde-proyecto`, que muestra una vista previa. Esa vista previa no cambia tu plan: lo confirmás vos después: con tu "dale" corre `rastro plan --desde-proyecto --confirmar`, que confirma la propuesta si no tenías plan vigente o acepta los ofrecimientos del repo si ya tenías uno. Ese comando no está preaprobado en `/rastro:init`. Cierra recomendando `rastro start`. Como el `npm link` apunta al marketplace clonado, `/plugin marketplace update rastro` actualiza también la CLI. Si el plugin se cargó con `--plugin-dir`, te sugiere instalarlo como marketplace; no toca tu shell. Escribe solo en `~/.rastro/`, en `.rastro/` del repo, en lo que escribe `rastro init` (`.git/hooks/post-commit`, `.git/info/exclude` y `.claude/settings.local.json`), en la CLI y el dashboard de la raíz y en la línea global del crontab. El plan sugerido se corre siempre, incluso en una segunda corrida con todo ya instalado: así `/rastro:init` refresca las sugerencias.
- `/rastro:plan <propuesta.md>`: arma el plan con vos y lo confirma solo con tu OK explícito.
- `/rastro:siguiente`: resume qué sigue y si vas atrasado (`rastro siguiente` y `rastro aviso`).
- `/rastro:dashboard`: abre el dashboard en el navegador. Corre `rastro start` en segundo plano (atado a la sesión), te dice la URL y, si ya estaba corriendo, solo lo informa. Si falla, explica qué falta y sugiere `/rastro:init`. Preaprueba solo `rastro.sh start`. También se pide hablando ("mostrame el dashboard", "quiero ver el Gantt"); con "qué sigue" o "cómo voy" no se abre.
- Skill `rastro`: indica qué comando de la CLI corresponde a "qué sigue", "cómo voy", "cambiá la duración de X" y "terminé X". Con "cerrá el día", "el update de hoy", "qué hice hoy" o "armá la daily" corre `rastro daily` (salvo que ya haya corrido hoy), resume y ofrece `daily --para-pegar` y `publish`; este último solo con tu OK explícito. Con "sincronizá el plan" o "traé el plan de Notion" corre `plan sincronizar` (vista previa, y `--confirmar` solo con tu OK); si preguntás "qué sigue" y cambiaste el plan en Notion, sincroniza antes, porque `siguiente` no lee Notion. Con "este repo es de X" cambia el repo de una tarea (`plan cambiar repo`) y con "sugerime el plan de este proyecto" corre `plan --desde-proyecto` (vista previa; con tu OK, `plan --desde-proyecto --confirmar`). `plan cambiar` y `plan sincronizar` andan desde cualquier carpeta; el resto de `plan` pide estar en un repo registrado. Con "mostrame el dashboard" o "quiero ver el Gantt" lo abre (`rastro start` en segundo plano). Solo publica en Notion con tu OK explícito, vía `plan sincronizar --confirmar` o `publish`. Preaprueba solo `siguiente`, `aviso`, `daily --para-pegar` y `start`.
- Hook `SessionStart`: si el repo está registrado (`rastro siguiente --si-registrado`), le da a la sesión el resultado de `rastro siguiente` como contexto (`scripts/contexto-sesion.sh`, sin LLM ni red).
- Hook `SessionEnd`: registra la sesión (`rastro hook session-end`). Si ya corriste `rastro init`, no se duplica.
- Hook `PostToolUse` (Bash): tras un `git commit` devuelve a la sesión el aviso de `rastro aviso`, salvo que la salida del commit ya lo traiga.
- `scripts/raiz-rastro.sh`: imprime la raíz del repo de Rastro, o sale con 1 sin salida.
- `scripts/dashboard-al-dia.sh`: imprime `al-dia`, `falta`, `desactualizado` o `sin-raiz` según `frontend/dist/version.txt` contra `frontend/package.json`; sale con 0 solo si está al día.
- `scripts/rastro.sh`: encuentra la CLI. Sin ella avisa por stderr y sale con 127; los hooks lo callan.

El hook de `SessionEnd` solo registra sesiones en proyectos donde corriste `rastro init`. Si el aviso dice que hay commits fuera del plan, nombrá la tarea con `[Tarea]` en el mensaje del commit.
